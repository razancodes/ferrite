# ferrite vs other CPU inference engines

Generated by `python bench/compare.py report` from `bench/runs/results.jsonl`.

Machine: i5-1135G7 (4C/8T, AVX-512 VNNI), 20 GB DDR4-2667 in flex mode, 5400 rpm HDD, Windows 11, on mains power. Engines: ferrite (this repo), llama.cpp b11425 (win-cpu-x64, `icelake` backend), mistral.rs 0.9.4 (CPU), OpenVINO GenAI 2026.4.1 (Intel's official Qwen3.5 IRs), HF transformers 5.15 / torch 2.9 (f32). Same Hugging Face checkpoints throughout; llama.cpp/mistral.rs files converted here with the same calibration text and amount as ferrite's (`bench/prepare.sh`).

Method notes: throughput is measured warm (a discarded warm-up first); ferrite loads with `FERRITE_LOAD=heap` (a sequential read into RAM, as llama.cpp and mistral.rs do; cold mmap page faults take tens of minutes on this disk); llama.cpp and mistral.rs get the best of 4 and 8 threads per metric; speed pools two passes run in opposite engine order; decode varies about ±10-15% run to run here (thermals, flex-mode memory placement). Perplexity uses `data/wiki.test.lf.raw` (LF line endings) because llama-perplexity converts CRLF itself; HF transformers f32 gives 15.3468 on the 0.8B windows. mistral.rs cannot load IQ4_NL tensors; ONNX Runtime GenAI 0.17.1 builds Qwen3.5 but fails to load it on CPU ("GetMemoryInfo for CPU should not be used").
